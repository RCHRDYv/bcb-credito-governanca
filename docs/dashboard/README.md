# Documentação do dashboard

O dashboard mostra onde uma financeira pode crescer em crédito para empresas e onde o risco está piorando. O trabalho é acompanhado no quadro [Dashboard de crédito PJ](https://github.com/users/RCHRDYv/projects/5).

| Documento | O que responde | Para quem | Situação |
|---|---|---|---|
| [Design system](design-system.md) | Como a interface se parece e se comporta: cor, tipo, espaço, vidro, movimento, componentes, padrões e modelos de página | Quem desenha e quem constrói as visões | Entregue, com o [protótipo navegável](../../dashboard/prototipo-design-system/index.html) |
| [Requisitos](requisitos.md) | O que o dashboard precisa fazer, para quem, como se confere e com que critério de pronto | Todos | Entregue |
| [Referências de design](referencias-de-design.md) | O que foi pesquisado, o que se aproveitou de cada referência e o que não serve | Quem avalia as escolhas de design | Entregue |
| Arquitetura | Como site, dataset e chat se ligam, e o que acontece quando um deles falha | Quem constrói e opera | A escrever, na #60 |

O contexto de produto (público, diferenciais e compromissos) fica em [`dashboard/PRODUCT.md`](../../dashboard/PRODUCT.md). As decisões ficam nos ADRs, do [0016](../adr/0016-site-estatico-no-github-pages-e-chat-no-zerogpu.md) ao [0020](../adr/0020-design-system-carbon-com-camada-liquid-glass.md).
